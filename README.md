# 🎓 경희대학교 성적 확인 알림 봇

Info21 포털을 주기적으로 모니터링하여 **성적 변동(미입력 -> 입력, 등급 변경)** 발생 시 **Discord**로 알림을 보내주는 봇입니다.

## ✨ 주요 기능
- **반자동 로그인 + 2차 인증**: ID/PW 입력·인증요청까지 자동, **OTP앱 푸시 승인만 사용자가 처리**
- **세션 유지(long-lived)**: 로그인 후 브라우저를 살려둔 채 주기적으로 접근해 세션을 유지
- **실시간 감지**: 성적 입력/수정·등급 변경 즉시 감지
- **Discord 알림**: 변동·인증요청·세션만료를 즉시 푸시 알림
- **Docker 지원**: 서버에 배포하여 24시간 가동

## 🔐 로그인 / 세션 동작 (중요)

이 학교 포털은 **로그인마다 2차 인증(OTP앱 푸시 승인)이 필요**하고, 인증 세션이 모두
**세션 쿠키(JSESSIONID)** 라서 브라우저를 닫으면 사라집니다. 그래서 봇은 이렇게 동작합니다.

1. **부트스트랩 로그인(반자동)**: 봇이 ID/PW 입력 → 인증방법 `OTP APP` 선택 → `Push 발송`까지 자동 수행하고,
   Discord로 **"📲 승인하세요"** 알림을 보냅니다. 사용자가 **경희대 OTP앱(KHU-OTP)에서 승인**하면 봇이 자동으로 로그인을 마무리합니다.
2. **세션 유지**: 로그인 후 브라우저를 닫지 않고, `CHECK_INTERVAL`마다 성적 페이지에 접근합니다.
   이 주기적 접근이 곧 **keep-alive(서버 유휴 만료 리셋)** 이자 변동 감지입니다.
3. **세션 만료 시**: 로그인 페이지로 튕기면 **자동 재로그인하지 않고** Discord로 `🔒 재로그인 필요`를 알린 뒤
   부트스트랩 로그인을 재수행합니다. 이때 **다시 한 번 폰 승인**이 필요합니다.

> ⚠️ 컨테이너를 재시작하면 세션 쿠키가 사라지므로 **재로그인(폰 승인)이 필요**합니다. 불필요한 재시작은 피하세요.

## 🚀 빠른 시작 (Docker, 권장)

서버(EC2, NAS 등)에서 가장 간편하게 실행하는 방법입니다.

1. **설정 파일 준비**
   `.env.example`을 `.env`로 복사하고 학번, 비밀번호, 웹훅 URL을 입력하세요.
   ```bash
   cp .env.example .env
   vi .env
   ```

2. **실행**
   ```bash
   docker-compose up -d
   ```

3. **로그 확인**
   ```bash
   docker-compose logs -f
   ```

## 💻 로컬에서 실행 (개발용)

**필수 요구사항**: Python 3.9+

1. **설치**
   ```bash
   git clone [REPO_URL]
   cd Grade-Check
   uv sync                                # 의존성 설치 (.venv 자동 생성)
   uv run playwright install chromium     # 브라우저 1회 설치
   ```

2. **설정**
   `.env` 파일을 생성하고 정보를 입력하세요. (위 Docker 방식과 동일)

3. **실행**
   ```bash
   # 브라우저 창을 보면서 디버깅하려면 HEADLESS=false
   HEADLESS=false uv run python grade_checker.py
   ```
   시작 직후 Discord로 **"📲 승인하세요"** 알림이 오면 폰에서 승인하세요.

## ⚙️ 설정 (`.env`)

| 변수명 | 설명 | 비고 |
|:---:|:---|:---|
| `LOGIN_URL` | Info21 로그인 주소 | 변경 X |
| `GRADE_URL` | 금학기 성적 조회 주소 | 변경 X |
| `PORTAL_ID` | 학번 | 필수 |
| `PASSWORD` | 포털 비밀번호 | 필수 |
| `DISCORD_WEBHOOK_URL` | 디스코드 웹훅 주소 | 필수 (알림용) |
| `CHECK_INTERVAL` | 확인 주기 (분) | 기본 30분 |
| `HEADLESS` | 헤드리스 모드 | 기본 `true` (로컬 디버깅 시 `false`) |
| `LOGIN_WAIT_SEC` | 폰 승인 대기 시간(초) | 기본 300 |

## ❓ 문제 해결

- **로그인 실패**: `.env`의 ID/PW가 최신인지 확인하세요. 비밀번호 검증 실패 시 2차 인증 단계로 넘어가지 않습니다.
- **폰 승인을 못 받음**: `LOGIN_WAIT_SEC`(기본 300초) 내에 OTP앱에서 승인해야 합니다. 놓치면 다음 주기에 다시 시도합니다.
- **성적 테이블 미감지**: 네트워크가 느리면 `grade_checker.py`의 `wait_for_selector` 타임아웃(기본 30초)을 늘려보세요.
- **headless 모드**: 서버에서는 `HEADLESS=true`로 동작합니다. 로컬에서 `HEADLESS=false`로 두면 브라우저 화면을 볼 수 있습니다.
